# egrpc Agent Instructions

## Overview

A gRPC client library for Erlang/OTP built on top of [gun](https://github.com/ninenines/gun). It
provides logical channels (resolver, subchannels with a pool of HTTP/2 transports, balancer, picker),
unary and streaming calls with attempts and retries, interceptors, pluggable codecs, and generated
stubs for the standard health and reflection APIs.

Downstream: [etcdgun](https://github.com/belltoy/etcdgun) depends on egrpc and is the main user of its interceptor and
channel APIs. Check it when changing those. The channel runtime is not designed around etcdgun, and
migrating etcdgun is not part of this repository's work.

The design notes (`REFACTOR.md`, the client design document) are local files and are not in the
repository. What a change must keep is in the Architecture and Gotchas sections below.

## Key constraints

**Generated code is read-only:** `src/stubs/*.erl` and `src/protos/*_pb.erl`.

- `src/protos/*_pb.erl` is generated by `rebar3_gpb_plugin` from `priv/protos/*.proto`.
- `src/stubs/*_stub.erl` is generated by `rebar3_egrpc_plugin` from the same protos.
- Regenerate with `rebar3 protobuf compile` then `rebar3 egrpc gen`. The pre-compile hook only runs
  in the `dev` profile, the default profile does not regenerate anything.
- Never edit generated files by hand, the changes are lost on the next generation. Change the protos or
  the plugin options in `rebar.config` instead.
- The plugin is used from the `redesign` branch of `rebar3_egrpc_plugin` until a release has
  `client_type`, `method_meta_type` and the `_stub` modules. After `rebar.config` changes the plugin, run
  `rebar3 plugins upgrade rebar3_egrpc_plugin`, otherwise the old one is used and nothing changes.

**Do not publish or tag on your own.** Releasing to hex and pushing tags is the maintainer's job. Only
do it when explicitly asked.

## Build and verify

Use the toolchain pinned in `.mise.toml` (Erlang 27.3, rebar 3.26.0, elp otp-27). Run every command
through `mise exec --`, because the shell may not have mise activated and PATH may point to old
versions:

| Command | Purpose |
|---|---|
| `mise exec -- rebar3 compile` | Build |
| `mise exec -- rebar3 eunit` | Run the inline eunit tests (`-ifdef(TEST)` in the modules) |
| `mise exec -- rebar3 ct` | Run the Common Test suites in `test/` (see Tests below) |
| `mise exec -- rebar3 do eunit, ct, covertool generate` | Run both and write the coverage report (Cobertura XML) to `_build/test/covertool/egrpc.covertool.xml`; `rebar3 cover -v` prints it |
| `mise exec -- rebar3 fmt -w` | Format with erlfmt |
| `mise exec -- rebar3 dialyzer` | Static analysis |
| `mise exec -- rebar3 xref` | Cross reference |
| `mise exec -- rebar3 ex_doc` | Generate docs into `doc/` (git-ignored) |
| `mise exec -- elp lint --module <mod> --include-erlc-diagnostics --experimental --read-config` | Lint one module |

### Tests

| Layer | Where | Run with |
|---|---|---|
| eunit, pure logic | inline in the modules (`-ifdef(TEST)`), for example `egrpc_error.erl`, `egrpc_grpc.erl`, the balancers and the backoff | `rebar3 eunit` |
| Common Test, fake server | `test/egrpc_unary_SUITE.erl`, `test/egrpc_gun_SUITE.erl`, `test/egrpc_channel_SUITE.erl`, `test/egrpc_interceptor_SUITE.erl`, `test/egrpc_call_credentials_SUITE.erl`, `test/egrpc_codec_SUITE.erl`; the server is `test/egrpc_fake_server.erl` (cowboy, h2c) which sends exactly the bytes a test asks for | `rebar3 ct` |
| Common Test, GripMock | `test/egrpc_gripmock_SUITE.erl`; starts the docker image `bavix/gripmock`, skipped when docker or the image is missing, or set `EGRPC_GRIPMOCK_ADDR=Host:GrpcPort:HttpPort` | `rebar3 ct` |

- `rebar3 ct --suite test/egrpc_unary_SUITE` runs one suite. The timeout cases wait for the real
  timeouts, a full run takes about half a minute.
- cowboy is a dependency of the `test` profile only, `~> 2.20`, tested with 2.20.0. rebar3 3.25.1 fails with 2.13.0 (`Dep ranch has invalid version`), 3.26.0 does not
  with `Dep ranch has invalid version`.
- `test/egrpc_test_echo_pb.erl` is generated from `test/egrpc_gripmock_SUITE_data/echo.proto`, the
  command is in the header of the suite. It is the only generated file outside `src/` and is committed.
- The tests named `no_leftover_*` in `egrpc_unary_SUITE` check that nothing of a stream is left in the
  caller's mailbox after a failed unary call. Run them a few times
  when touching `egrpc_transport_http2:discard/1`, the race is what they guard against.
- The fake server takes cowboy options as its second argument: `max_concurrent_streams` makes it
  send that SETTINGS value, `listen_port` makes it listen on a given port (to bring a server back on
  the port a channel knows). GOAWAY is made by `sys:terminate/2` of a connection process of ranch.
- The tests of a channel stop it in `end_per_testcase`: a channel which is not stopped keeps
  reconnecting in the background.
- `test/egrpc_test_recorder.hrl` is the interceptor, stream hooks and attempt hooks of the tests;
  `egrpc_test_recorder` and `egrpc_test_recorder_b` are two tags of it.

## Architecture

The modules are in `src/` by part: `balancer/`, `call/` (call, attempt, retry, stream), `channel/`
(coordinator, subchannel, picker, registry and the supervisors), `client/` (the calls, behaviours of
interceptors and credentials, errors), `resolver/`, `transport/` and `codec/`. `egrpc`,
`egrpc_app`, `egrpc_sup`, `egrpc_codec` and `egrpc_grpc` are in `src/`. The names do not change with
the directory.

| Module | Role |
|---|---|
| `egrpc` | Public types only (`client()`, `channel()`, `stream()`, `grpc()`, `method_meta()`, ...) |
| `egrpc_client` | The calls the generated stubs make: `unary/4`, `server_streaming/4`, `client_streaming/3`, `bidi_streaming/3`; the first argument is a channel name or a channel |
| `egrpc_channel` | A logical channel: `start/2`, `stop/1,2`, `await_ready/2`, `update_endpoints/2`, `derive/2`, `ref/1`, `info/1,2`; the `gen_server` which is the coordinator (owns the balancer state and the subchannels, publishes the picker, wakes the calls which wait for a picker) |
| `egrpc_call`, `egrpc_attempt`, `egrpc_retry`, `egrpc_deadline` | A logical call (what the interceptors see), one network attempt (credentials, pick, open the stream, `done` feedback), the retry engine with the budget, the absolute deadline |
| `egrpc_stream` | One attempt as the application holds it: `send_msg`, `recv_header`, `recv_msg`, `recv_response`, `parse_msg`, `cancel_stream`, and the unary response with the cleanup of a failed call |
| `egrpc_interceptor`, `egrpc_stream_interceptor`, `egrpc_attempt_hooks` | Behaviours: `unary/3` of a logical call, the hooks of a stream, the observers of an attempt |
| `egrpc_credentials`, `egrpc_transport_credentials` | Call credentials (metadata of every attempt), transport credentials (TLS options) |
| `egrpc_resolver`, `_static`, `_dns`, `egrpc_resolver_worker` | Target to `#egrpc_endpoint{}`, the process which calls the resolver and tells the coordinator |
| `egrpc_balancer`, `_pick_first`, `_round_robin`, `egrpc_picker` | Pure state machines which give actions (create, remove, connect a subchannel) and an immutable picker snapshot |
| `egrpc_subchannel`, `egrpc_subchannel_sup` | `gen_statem` of one endpoint: owner of its transports, reconnect with backoff, writes its row in `egrpc_transports` |
| `egrpc_transport_pool`, `egrpc_transport_picker` | The data structure of the transports of a subchannel; the choice among them from the ETS row and the `atomics` of the subchannel (runs in the caller) |
| `egrpc_transport`, `egrpc_transport_http2` | The behaviour of a transport and the one on gun |
| `egrpc_codec`, `src/codec/*` | Codec behaviour and implementations: `egrpc_proto`, `egrpc_json`, `egrpc_erlpack` |
| `egrpc_grpc`, `egrpc_error`, `egrpc_status`, `egrpc_metadata`, `egrpc_method` | Message framing; `grpc-status` to `{grpc_error, Name, Message}` and `class/1`; the status record for the retry and feedback; metadata lists; what the runtime needs of a method |
| `egrpc_registry` | Owns the tables `egrpc_channels` (the desired state: the options), `egrpc_pickers` (version, picker, channel ref, connectivity) and `egrpc_transports` (the row of every subchannel); removes what is left of a channel whose supervisor is gone |
| `egrpc_channels_sup`, `egrpc_channel_sup` | The supervisors, see below |
| `egrpc_app`, `egrpc_sup` | Application callback; `egrpc_sup` supervises the registry and `egrpc_channels_sup` (`rest_for_one`) |

The public records (`#egrpc_endpoint{}`, `#egrpc_address{}`, `#egrpc_resolver_result{}`,
`#egrpc_pick_info{}`, `#egrpc_pick_result{}`, `#egrpc_pick_done{}`, `#egrpc_status{}`,
`#egrpc_transport_credentials{}`) are in `include/egrpc.hrl`; the internal ones (the channel ref, the
call, the attempt, the transport ref) are in `src/egrpc_internal.hrl`, use the accessors.

A channel (`egrpc_channel:ref()`) is a plain record, it holds no connection: every attempt reads the
picker from `egrpc_pickers` by its name. The calls are made in the calling process, no process is on
the path of a call; the processes only keep the subchannels, the transports and the picker up to date.

```
egrpc_sup (rest_for_one)
 |- egrpc_registry
 `- egrpc_channels_sup (simple_one_for_one)
     `- egrpc_channel_sup (for each channel, one_for_all)
         |- egrpc_subchannel_sup -- egrpc_subchannel (for each endpoint)
         |- egrpc_channel
         `- egrpc_resolver_worker
```

A channel which crashes takes its subchannels with it (`one_for_all`) and starts again from the
options in `egrpc_channels`; the transports reconnect.

## Gotchas

- **gun does not retry by default:** `egrpc_transport_http2` sets `retry => 0` in the gun options
  and the subchannel does the reconnect, so `gun_opts` can not change it. When a connection can not
  be established the gun process exits.
- **`close` is graceful:** `egrpc_transport:close/1` is `gun:shutdown/1`, and the connection may
  linger until the server closes it. A subchannel which is removed closes its transports this way.
- **gun messages go to the requesting process.** Responses of a stream are delivered to the process
  which made the request, and `gun_up`/`gun_down` go to the process which opened the connection,
  which is the subchannel. The holder of a stream gets `{gun_error, _, _, closed | {closed, Reason}}`
  for every stream when the connection is lost, before the owner gets `gun_down`.
- **Interceptors** are one list in the `interceptors` option of `egrpc_channel:start/2` and
  `derive/2`: a module (which implements `unary/3` of `egrpc_interceptor` and/or the callbacks of
  `egrpc_stream_interceptor`) or a `fun/3` which wraps unary calls. The first element is the
  outermost, all of it runs in the caller process, once for a logical call. There is no state by
  position and no `init/1`, keep state in the attributes of the call or of the stream. The stream
  hooks do not fire for unary calls. `unary_interceptors` and `stream_interceptors` are not options
  any more, `start/2` raises `error({invalid_option, Key})` for them.
- **`call_credentials`** is a module, `{Module, Context}` or a `fun((CallInfo) -> {ok, Metadata} |
  {error, Reason})` of `start/2` and `derive/2`, called in `egrpc_attempt` for every attempt of a
  unary call and when a stream is opened. The metadata of the call takes precedence, `grpc-` keys are
  dropped, `{error, Reason}` gives `{error, {call_credentials, Reason}}` without sending, an
  exception of the callback is not caught.
- **The codec** is the `codec` option of `start/2` only (default `egrpc_proto`, not an option of
  `derive/2`). A codec implements `init/1` and `content_type/0`, the latter is the `content-type`
  header of the requests. `egrpc_json` needs OTP 27 (`json` module) and a pb module generated with
  gpb's `json` option.
- **A hook can stop a call** by returning `{error, Reason}`, so `egrpc_stream:send_msg/3` and
  `close_send/1` return `{ok, Stream} | {error, Reason}`. `recv_msg/2` returns `eof` at the end of a
  stream with status OK.
- **The unary response timeout** is `timeout` in the call options, 5000 ms by default, for each wait
  for a message (not a deadline, not sent to the server). After a failure other than a status of the
  server, the transport's `discard/1` cancels the stream and flushes the mailbox of the caller.
- **`deadline`** in the call options is the time of the whole call in milliseconds, relative.
  `egrpc_call:new/3` turns it into an absolute monotonic time before the interceptors, so that all
  the attempts share it. It is sent as `grpc-timeout`, and the end of it is
  `{error, {grpc_error, deadline_exceeded, _}}`. Do not confuse it with `timeout`.
- **Errors keep the raw reasons of gun** (`timeout`, `{stream_error, {goaway, _, _}}`, ...).
  `egrpc_error:class/1` is what tells `not_sent` from `unknown`; do not add a wrapper tuple to the
  result of the calls. `{goaway, _, _}`, `closing` and `{stream_error, refused_stream, _}` are `not_sent`,
  `{closed, _}` and `{down, _}` are `unknown`.
- **Calls never wait for a connection by default:** with no subchannel which can take the call the
  result is at once `{error, {grpc_error, unavailable, _}}` (it is not retried: no attempt was
  made), `{error, channel_not_found}` when the name is not registered. `wait_for_ready => true` in
  the call options waits for a new picker until the deadline. `start/2` is asynchronous and
  `await_ready/2` is how to wait.
- **Nothing of a channel is kept in `persistent_term`**, its channel ref with the pipeline is in the
  row of `egrpc_pickers`, the picker is there too.
- **A channel has to be stopped.** It keeps retrying when no endpoint can be reached, there is no
  limit. `stop/1` removes the picker row first, waits for `inflight` to be 0 or for the timeout
  (5000 ms), then closes the connections.
- **The registry entry of a channel holds its desired state** (the options). `update_endpoints/2`
  writes the new target in it before it applies it, and a restarted channel reads it. The picker,
  the rows of the subchannels and the `atomics` are the observed state and are rebuilt.
- **Retries are made in `egrpc_retry`, below the interceptors and above the attempt.** Every
  attempt picks again (`egrpc_picker`) and goes through `call_credentials`; the interceptors run
  once for the logical call. Only with the `retry` option of the channel or of the call.
  The budget (`atomics`, in thousandths of a token, `compare_exchange`) is for the channel.
- **The idempotency of a method** is `proplists:get_value(idempotency_level, Opts)` of the
  `opts` of `rpc_def` in the `Grpc` map (`'IDEMPOTENT'`, `'NO_SIDE_EFFECTS'`, or not set). gpb puts it
  there, the plugin does not have to.
- **`previous_subchannels`** of `#egrpc_pick_info{}` are the subchannels which the earlier attempts
  of the call used. A picker avoids them when it has another, it does not fail when it has not.
- **`atomics` of a subchannel** (`3 * max_connections` slots, see `egrpc_transport_picker`):
  `inflight` for each transport (unary calls, `try ... after` in `egrpc_attempt:unary/4`; the place is
  reserved with `add_get` and given back when it is over the limit, so the limit of the peer holds
  for unary calls), a `draining` flag for each transport which a caller sets when it saw `goaway`
  or `closing` (the subchannel clears it when the transport is up again), and a count of the calls
  given to each transport for the scale down. Streams are not counted. Do not make the owner of a
  stream a counted object: the owner of a stream may be gone without giving the place back.
- **The maximum number of concurrent streams of the peer** is read from
  `{gun_notify, ConnPid, settings_changed, Settings}`, which gun only sends when
  `http2_opts => #{notify_settings_changed => true}` is set (`egrpc_transport_http2` sets it), and
  only to the owner of the connection, the subchannel. It is `infinity` until the peer sets it.
- **The connectivity of a subchannel is derived** from its transport pool
  (`egrpc_transport_pool:connectivity/1`), not set by events one by one: `ready` while a transport
  takes calls. The RPC results never change it, they are `done` feedback to the picker.
- **`info` is a per-channel term** of the pipeline, set by `start/2` or `derive/2`, not meant for
  per-call data (use the attributes of the call).
- **A channel ref is a value, not a handle:** `derive/2` returns a ref which has the same name and
  subchannels, there is nothing to close.
- **`maybe` expressions are used**, with `-feature(maybe_expr, enable)` in the modules.
- **Keep the versions in sync** when preparing a release: `vsn` in `src/egrpc.app.src` and the
  dependency snippet in `README.md`. egrpc does not send a `user-agent` header.
- **`.elp_lint.toml` is only read with `--read-config`**, and it is a local file: it is excluded
  through `.git/info/exclude` and is not in the repository. elp 1.1.0 (otp-27) needs the `linters`
  table; the old `enabled_lints`/`disabled_lints` keys are rejected with `unknown field`. Write
  `enabled = false`, `disabled = true` is accepted but has no effect:

  ```toml
  [linters.W0038]
  enabled = false
  [linters.W0051]
  enabled = false
  ```

  `W0038` (old edoc syntax) is intentionally disabled, do not "fix" it. It would be reported for the
  generated stubs which can not be edited.
- **Git-ignored files:** `doc/`, `rebar.lock`, `.mise.toml`, `config/sys.dev.config`,
  `rebar3.crashdump`, and `.elp_lint.toml` (locally excluded). Do not commit them.

## Not built

The active mode of streams (a relay process for each stream), counting of streams, resolvers
other than static and DNS (xDS, SRV), telemetry, hedging, outlier detection (the `done` feedback of
the picker is there for it), TLS options for each endpoint.

## Conventions

- Match the surrounding code: comment density, naming, edoc (`%% @doc`) for exported functions.
- Commit messages are short and imperative, optionally with a type prefix (`fix:`, `doc:`).
- When changing the interceptor or channel behaviour, add or update tests. etcdgun is
  checked when the options of `start/2` or the interceptor behaviour change; it is not a reason to
  change the channel runtime.
- Local `*.md` files (design notes, discussions) are not committed.
